# 审阅结构与验收

## 两页，同一份 XMind

审阅索引：项目 → 原业务分组/阶段/对象 → 编号与完整标题。节点显示原优先级、原设计状态、底线状态；备注写来源及到“详细用例”页按编号查找的提示。索引不是另一套用例，不重复计数。

详细用例：沿同样分组列全部用例 → fields 中的完整内容。列表保留顺序；对象保留键和值及层级；多行文本不截断。每条用例的原生 notes 保存来源、导入编号说明及完整归一化用例 JSON，便于追溯。来源备注不等于实际执行证据。

优先保留已有 A1 等需求分组；无分组时根据资料选择业务阶段或对象。不要在业务主题旁另造一层“权限/异常/并发大杂烩”打散上下文。相同分组路径复用，同名的不同父分组保持分开。

底线是已有分类的呈现，默认未评估。索引标签明确“已核定底线/底线候选/有替代/非底线/未评估”，不能用同一种红色或同一个“核心”标签抹掉差别。脚本不重新做不可替代性判定。

为保留长步骤与正文，不做固定字符截断。导图较大时可在客户端收起用例子节点，索引页始终用于快速浏览；用户明确要求分文件时按已知业务范围分批，另留完整编号索引，不能为了小图漏掉用例。

## 交付验收

1. 原文范围核对：编号/导入映射、唯一数量、抽取问题、同号冲突及多文档去重有据。
2. 机械回读：归一化输入与两页节点、完整字段、标签、原生备注、索引对应一致。
3. 复杂结构：并发参与者与同步顺序、分步断言、数据准备引用、长文本及中文字符保留。
4. 实机显示：在实际可用且获准的客户端打开生成文件，查看中文、原生备注、结构及代表性复杂节点；记录客户端版本、实际观察和证据。未打开不标已通过。
5. 审阅效果：真实接收者能否找到用例、理解路径、识别缺口；保留具体反馈。作者自查或脚本退出 0 不能代替。

失败示例：只交 Markdown 改后缀；标题在图里但步骤丢失；P0 自动标已核定；人工子集冒称全部；空预期被补为“系统正常”；图的索引和详情不同步；未打开却写“可正常打开”。这些情况均须纠正或明确缺口。

## 格式来源与限制

生成器采用 ZIP 中 content.json、metadata.json、manifest.json 的现代 JSON 封装，sheet/topic、attached 子节点、plain 原生 notes 和 labels 的结构对照 [Xmind 官方生成器 serializer.ts](https://github.com/xmindltd/xmind-generator/blob/af8e66ab57f480854671a45bccaa029151977534/src/internal/serializer.ts)；核对日期 2026-10-17。

本助手独立实现保真转换，只依赖 Python 标准库，不捆绑该第三方项目。它不包含 XMind 渲染器、客户端或在线预览服务；机械回读不能证明所有客户端版本的布局和打开兼容性。XMind 8 旧版 XML 格式不在此版输出范围，遇到指定旧客户端需如实说明并另评估兼容输出，不能悄悄换格式后仍称已验证。
