# 测试：用例转XMind

版本：1.0.0。调用 $system-testcase-xmind。历史见 [CHANGELOG](CHANGELOG.md)。

## 职责与输入

一个目的：已有用例 → 保真整理与审阅结构 → 可编辑的 .xmind。

接收用户指定的 Markdown、Excel、Word、JSON、文字用例或已有用例提纲；读取对应内容后转换。脚本只接收归一化 JSON，其他格式由当前环境的适用阅读工具提取，不声称脚本能直接解析任意文档。只有需求而无用例时，说明需要先完成设计；本技能不擅自编造用例补齐导图。

默认转换指定范围的全部用例，不因执行者是 AI 或人工而筛掉。只读源文档，生成物写到本批次新目录。重复调用生成新批次，不覆盖原用例、旧导图或人工审阅批注。

## 转换

1. **固定来源和范围**：确认具体文件、版本、用例范围与可读取内容；记录文件指纹及章节、表名行号或 JSON 定位。先读 [输入协议](references/input-contract.md)。
2. **整理唯一用例**：沿用原编号、标题、业务分组和顺序。无编号时建立导入编号及原位置映射；重号不同义先列冲突，不静默去重或改写。全量与底线文档中同一编号、同一正文只保留一条，合并来源；冲突保留待处理，不凭优先级决定版本。
3. **保留完整含义**：前置、准备与数据、角色权限、状态、动作、逐步预期、断言与取证、风险、清理、引用和缺口均可进入字段。共享准备或规则须带上可审阅内容或明确定位，不能只留下无从查阅的编号。未知字段放入 fields，不因模板没有列就丢弃。
4. **组织审阅**：按 [导图约定](references/review-layout.md) 生成“审阅索引”和“详细用例”两页。分组优先沿用来源，其次按业务阶段或对象；权限、并发、幂等归入所属业务。保留原优先级；已核定底线、候选、有替代、非底线、未评估分开，不由 P0 自动升格。
5. **生成并回读核对**：运行下面的 build，再用 check 独立回读。核对唯一编号集合、完整字段、原生来源备注、索引与详情对应、缺失项及底线状态。机械核对只证明归一化 JSON 到导图的保真；还须对照原始文档，特别检查抽取、合并单元格、共享引用和范围选择。
6. **交付及回收**：若有获准可用的 XMind 客户端，打开实际导图核对中文、多行文本、备注和代表性复杂用例的显示；没有客户端则交付制品并明确“尚未实机打开”。按 [效果回收](references/outcomes.md) 保存批次、实际问题和后续反馈。

源文缺少步骤或预期时明确标“未提供（源文未记录）”，列入核对清单；不为了导图好看删掉缺口或编造预期。设计、准备、执行结果是不同字段，转换成功不代表用例可执行、评审通过或测试通过。

## 运行

使用 Python 3.10+ 标准库，无需第三方运行包。脚本路径解析到本 skill 实际目录。输出目录必须尚不存在。

~~~powershell
python -X utf8 -B scripts/xmind_review.py build --input "批次输入/review-cases.json" --output-dir "输出/新批次"
python -X utf8 -B scripts/xmind_review.py check --input "输出/新批次/review-cases.json" --xmind "输出/新批次/测试用例.xmind"
python -X utf8 -B scripts/xmind_review.py review --record "输出/新批次/xmind-review-record.json"
~~~

输入写法见 [虚构样例](assets/example-cases.json)。它只演示转换，不是任何真实项目的业务规则或使用反馈。

## 交付

- 测试用例.xmind：可编辑导图，索引与详情在同一文件。
- review-cases.json：归一化机器源，保留原编号或导入编号映射。
- 转换核对.md：范围、数量、缺失项和校验边界；补记对原文的核对及真实客户端检查。
- xmind-review-record.json：映射、指纹、转换检查与后续反馈，放在项目输出，不装入 skill。

现代 JSON 格式的封装依据见 [格式来源与限制](references/review-layout.md#格式来源与限制)。不以改后缀的文本冒充 XMind。脚本默认不覆盖已有目录；失败修正输入后使用新目录，保留实际错误原因。

## 查看效果

“查看这次转 XMind 的效果”时，读取指定批次记录并运行 review，先列漏项、映射问题、打开失败及未核实项，再展示实际评价。只读该记录，不重新转换、不自动联络审阅者。没有真实反馈写未评价；没有实机打开记录写尚未核实。界面美观和业务审阅帮助不能由 ZIP/JSON 校验替代。
