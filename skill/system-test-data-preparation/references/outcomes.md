# 前置准备效果回收与查看

采用可读的 前置准备反馈.md。由AI按用户请求读取指定报告和记录并汇总，无后台采集、必装助手或自动回访。

## 初始化与事件

批次头：run_id、revision=1、system-test-data-preparation/1.0.0、模式、报告/分配清单路径及实际指纹或精确版本、源用例基线、目标环境和部署。初始写“尚无使用记录”“未评价”，作者演练另列。

实际事件表每行记：事件ID、带时区时间、skill版本、准备批次、报告revision或指纹、对象（用例/分支/DATA/CAP/BLK/整份）、实际使用范围、观察或原话、来源定位、处理状态及下一步。

可回收内容：

- 下游接手时前置是否确实可用、合法链和身份是否正确、数量隔离是否足够、报告能否定位对象与证据。
- 报为就绪后暴露的前置缺口，原因是漏核、状态漂移、部署/角色变化、外部依赖还是尚未确定。
- 漏报阻塞、错误阻塞、模糊输入请求、错误复用/重复创建、意外副作用及恢复情况。
- 表达是否易懂、交接是否可用、失效提醒是否准确。每维度按真实反馈记满足/不满足/未评价；整份“有用”只记录原话，不摊到每项。

错误就绪需核对该报告所声明时间、适用环境、对象和有效条件；后续状态变化不自动证明原报告错误。执行产品断言失败也不能自动归咎于准备，需关联证据确认因果。阻塞解除、准备练习成功或用例通过都不单独代表skill整体有效。

## 问题处置

问题用稳定FB编号，状态为待核实 / 已确认待处理 / 已修订待复核 / 复核关闭 / 反证撤销 / 待裁定。关联原事件、证据及影响分支；采纳不是确认，修改不是关闭。准备报告BLK的“已解除”必须有本轮解除证据，不用反馈的口头采纳代替。

仅追加反馈时保留旧revision快照，核对并发变化后增加revision，历史和反证不删。准备对象、结论或部署变化后新建核实批次并保留DATA/CAP/BLK映射；skill逻辑变化另行升版。不要让旧版/历史批次的好评成为新批次的实际效果。

## 只读查看入口

请求示例：“使用 $system-test-data-preparation 查看这次前置准备效果，报告和反馈在项目批次目录……”。执行：

1. 读取指定文件及获准证据，核对批次、技能版本、报告版本、用例/环境基线和对象定位；缺文件明示，不扫描无关私有目录。
2. 先列未关闭的错误就绪、真实前置缺口、副作用、未解阻塞及反证争议，再列已确认的可用范围和处置情况。
3. 分开呈现准备质量（作者检查/演练）、实际下游使用和接收者评价。没有实际记录写尚无使用记录，未提供评价写未评价；不能据此推断从未发生使用。
4. 同对象/维度取最后一次实际评价，显式未评价可撤回当前判定，保留所有历史。统计时去重到明确对象，分母仅含该维度真实非空评价；不拿用例总数、重复事件或BLK数量作满意率分母。无分母不报0%/100%。
5. 不同skill版本、部署及批次分别显示；若用户要合并趋势，说明选择范围和可比条件。未保存的实际ID/版本不补猜。
6. 仅基于已见偏差提出可验证改进；没有可比前后实际基线不声称节省造数时间、提高执行通过率或减少业务事故。

查看不重新准备、执行正式用例、外发、找人评价或安排定时任务。应用改进按当前授权修改并升版；只查看不自动改skill、源用例或共享知识。
