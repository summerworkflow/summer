# 前置交接与就绪判定

本协议用Markdown表格即可实施，无必装脚本。用户已有表格或机器协议时等价映射；不强制把用例转成某种JSON，也不把人工核对称为程序校验。

## 批次头

每个批次记：run_id、报告revision、skill ID/版本、创建/核实时间及时区、模式（规划/实际准备/只读复查）、选定用例和分支、输入文档路径与版本或实际指纹、规则依据、评审遗留、明确排除、目标环境/部署/配置、角色数据范围、适用授权及准备写入边界。

缺失事实写“未知”，未验证写“未验证”，实际结果留空；不得填样例ID或当前系统输出作为独立预期。输出包含实际业务ID时按项目数据规则保存在授权项目范围，技能包内不得夹带。

## 前置准备报告.md

先列影响高风险分支的缺口，再列已核实事实。建议保留以下章节：

1. 范围与结论：规划完成、部分就绪或全部选定分支在核实时间点就绪；说明未执行正式用例及未证实的范围。
2. CAP能力表：CAP编号、用途、依赖、影响分支、资产/版本/成熟度、本轮状态、最小练习及成功标准、实际结果/证据、下一步。
3. 分支就绪表：用例/分支、DATA/CAP、能力、样本、环境角色、预期依据、总判定、核实时间/证据、有效条件/执行前复查。
4. BLK阻塞表：编号、类型、影响用例/分支、失败阶段/事实、已做尝试、所缺精确输入、可继续分支、解除条件/下一步。
5. 操作/练习记录：真实调用入口或操作、版本、输入标识、实际新增/修改对象、结果与异常、副作用/保留方案、证据定位；规划时明确无实际操作。

能力表的“本轮验证通过”需本轮匹配环境和身份的证据；其他状态不可按ready使用。可只读复用数据的分支不必虚构“新建数据能力”作为依赖。

## 分支就绪表的四个维度

每个维度使用：就绪 / 待验证 / 阻塞 / 已失效 / 不适用；必须有原因和事实/来源。

| 维度 | 判就绪需要什么 |
|---|---|
| 准备能力 | 本分支必须依赖的CAP及上游已在本轮适用范围验证；只读已有样本不依赖创建能力时明确不适用理由 |
| 实际样本 | DATA分配确有实际对象，身份、归属、关系、关键值、动作前状态、持久性和本轮数量/隔离要求有证据；计划模板和历史成功不算 |
| 环境角色 | 当前环境/部署配置和已登录身份的数据范围、动作权限及必要工具适用；秘密信息不进报告 |
| 预期依据 | 所需业务规则/基线适用且独立于被测输出，计算精度和证据获取方式可落实；争议待裁定就保留阻塞 |

总判定规则：

- **规划未验证**：模式是规划，无论资料多完整都不报当前分支就绪；历史/既有证据可引用但不冒作本轮核实。
- **已阻塞**：至少一个必要条件已确认不满足或不可达；保留其他未知/失效维度，不能被一个总状态遮住。
- **需复查**：必要条件的前次证据已失效且尚未重核；失效范围不能按旧值继承。
- **待验证**：无已知阻塞，但至少一个必要维度尚未有足够当前证据。
- **本轮就绪**：四个维度均就绪或有可核对的不适用理由，并且没有其他未解的必要条件。注明核实时间、适用范围和执行前复查项。

不能把必要条件标“不适用”来绕过未验证。一个分支就绪不代表同用例其他分支或全部用例就绪；底线用例沿用上游标记，不由准备skill重新核定。准备总判定不是测试Pass/Fail。

## 前置数据分配清单.md

一条DATA对应一个可明确交接的分支/轮次分配，复杂链可多条关联：

| 字段组 | 必须能定位的内容 |
|---|---|
| 关联 | DATA编号、用例/分支/轮次、上游DATA与CAP、来源用例版本 |
| 目标 | 被测动作、动作前对象状态、刻意无效条件、合法源链、父子/关联关系 |
| 业务值 | 类型/方向/变更、组织/租户/角色、主数据、金额数量币种日期精度、附件、规则及独立预期依据 |
| 分配 | 来源/复用或新建、每轮数量、共享/隔离/消耗策略、计划唯一标识、实际稳定ID（未创建留空） |
| 本轮事实 | 环境/版本/角色范围、核实时间、身份关系状态关键值及持久性证据、与计划的偏差 |
| 恢复交接 | 重试标识及首轮关联、未知写入的查证方式、保留/清理授权、失效条件、执行前复查、当前阻塞 |

源用例没有授权修改时，把此表作为补充交接，保持原文件。前置变化导致预期不再适用时先定位问题，不能用准备表覆盖业务规则。

## 虚构示例：报告应如何诚实表达

输入：TC-01审批动作、TC-02已批准单据的只读查询。历史脚本能生成“已批准”样本，当前环境自动审批且未核实登录角色。

| 分支 | 能力 | 样本 | 环境角色 | 预期依据 | 总判定 |
|---|---|---|---|---|---|
| TC-01/待审批 | 历史验证待复核，归入待验证 | 确认当前链无法停在待审批，阻塞 | 身份范围待验证 | 假定已提供确认规则 | 已阻塞；需合法状态控制 |
| TC-02/查询 | 若只读已有样本则创建能力不适用 | 尚未查证实际对象，待验证 | 待验证 | 假定已有适用查询规则 | 待验证；可独立核实 |

此表只是示意，实际报告不能继承“假定”事实。若本次仅规划，两行总判定均写“规划未验证”，另列已知限制，不填实际ID和成功结果。
