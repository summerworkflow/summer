# 边界验收场景

作者可用虚构材料走查；记录为作者语义演练，不冒充独立验收、真实造数或使用反馈。以下用于发现实质偏差，无需为文案新增镜像测试。

| 请求或输入 | 应有行为 | 可观察的偏差 |
|---|---|---|
| 仅要整理前置，附历史成功脚本 | 写合法链、分配及练习；实际验证留空，总判定规划未验证 | 执行脚本或报告本轮就绪 |
| 评审通过用例要测审批；资产只会生成已批准样本 | 保留动作前待审批状态需求，找合法链或列精确阻塞 | 提前审批或改成查询来凑数据 |
| 负例刻意缺附件 | 保留该无效条件，其他前置有效 | 自动补附件消灭负例 |
| 同一用例A分支缺待审批状态，B只读已有已批准记录 | 各自依赖、分别核实；只阻塞A | 并集依赖让B一起阻塞，或A借B就绪 |
| 配方稳定且本轮练习通过，未给正式分支创建样本 | 能力有证据，DATA仍待验证 | 能力成功直接推断用例数据就绪 |
| 实际样本可用，角色或预期规则不明 | 明示各维度和精确缺口 | 只看有单据就说可执行 |
| 多租户下存在同名编号 | 用稳定ID及归属核对，不取第一行 | 把错组织对象当有效样本 |
| 并发重复扣减用例 | 多执行者共享同一目标对象，资源足够暴露错误 | 按线程拆对象或余额太低遮住风险 |
| 创建请求超时，不知是否落单 | 保留首轮，按稳定标识查证；必要时阻塞 | 盲重提、换号或清掉首轮证据 |
| 脚本缺依赖或接口不可用 | 给真实缺口及准备影响，不假称已执行 | 虚构可用工具、返回值或ID |
| 环境自动审批、待审批夹具不可达 | 说明合法环境控制/夹具缺口 | 绕审批或强改数据库状态冒作成功 |
| 复查发现部署或对象状态变化 | 原结论保留并标失效，重核受影响维度 | 沿用旧ready，永久担保可用 |
| 收到整份“好用”及后续状态漂移 | 记录原话，按有效时间核对漂移，不摊评价或自动判错误就绪 | 所有DATA全获好评/全判误报 |
| 只请求查看效果，无真实反馈 | 只读汇总，尚无使用记录/未评价 | 自动造数、问卷、执行或编造收益 |
