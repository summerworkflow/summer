# 测试：前置准备

版本：1.0.0。历史见 [版本记录](CHANGELOG.md)。调用 $system-test-data-preparation。

## 职责与入口

输入已有用例及适用业务依据，倒推合法准备链，形成可交接的前置方案或本轮已核实的就绪清单。准备能力、实际样本、环境角色和预期依据分别判断；一个维度就绪不能代替其余维度。

- “整理前置、准备方案、需要哪些数据”：只读获准资料并规划，实际对象和验证结果留空。
- “准备测试数据、验证前置、补齐阻塞”：沿当前环境、对象和副作用授权实际准备；已有适用授权继续使用。无法获准的动作留具体阻塞，不扩大到付款、审批、赋权、生产修复等未授权范围。
- “复查是否就绪”：只核实指定对象和依赖，保留前次结论及失效原因；不顺带执行被测动作。
- “查看前置准备效果”：只读指定报告、反馈和获准证据，按 [效果协议](references/outcomes.md) 展示。

创建本skill不意味着本轮获准开展真实业务准备。资料中的示例、账号名、脚本和历史成功不构成本轮授权或当前事实。

## 准备流程

1. **固定范围和基线**：识别选定用例、分支、版本、评审遗留、适用规则、目标环境及已有授权。缺信息只阻塞受影响分支，其他部分继续。待确认或用户排除项单列，不偷改用例和预期。
2. **从被测动作前一刻倒推**：按 [准备方法](references/preparation-method.md) 写目标状态、源对象、合法操作链、关系、角色、主数据和附件。准备终点必须保留被测动作及刻意无效条件。
3. **核对可用资产和依赖**：查指定知识/资产目录；核实配方、脚本、版本、参数、依赖、环境和副作用。能力用稳定CAP编号及有向依赖表示，数据分配用DATA编号。先解上游，再优先解锁高风险及更多选定分支；不套用其他业务分支的依赖。
4. **决定复用、创建或补能力**：按分支分配可重复读取、可变或会消耗的样本及每轮数量。脚本存在不等于可用；仅规划写最小验证练习，实际准备才做获准的隔离验证。没有工具就写真实缺口，不假称具备接口、数据库或浏览器执行能力。
5. **记录当前核实事实**：实际准备核对对象身份、归属、父子关系、目标状态、关键值及刷新/重入后的持久性，并记录环境、版本、角色范围、时间和证据。结果不确定时先查证，不盲目重提；失败样本和首轮证据保留。
6. **按分支交接**：依 [报告协议](references/report-format.md) 交付前置准备报告及分配清单；分别列就绪、待验证、阻塞、已失效和不适用。已就绪记录注明有效条件和执行前复查项，正式用例结果保持未执行。

开始交付前按 [边界验收](references/acceptance.md) 自查；参考来源及不继承的规则见 [借鉴说明](references/sources-and-boundaries.md)。

## 输出与衔接

默认保存三份可读文件到项目批次目录：前置准备报告.md、前置数据分配清单.md、前置准备反馈.md；小批次可以合并章节，保留编号和定位。初始化反馈，不代填真实评价。

不要求固定框架或机器协议；用户已有表格/JSON协议时保留其结构并补齐必要字段，无法等价映射的内容写补充记录，不伪称已有解析器校验通过。完整字段、就绪判定与示例见报告协议。

交给执行者的是实际对象、依赖、前置证据、边界与阻塞；准备练习成功不是正式用例通过。源用例不符或预期缺依据时给出可定位问题，沿已有授权修订，否则交回设计/评审处理。不会自动设计整套用例、转AI脚本、执行正式测试、提交Bug或改共享知识库。

## 效果回收与查看

用户可说：“查看这次前置准备效果，报告和反馈在……”。只读指定批次，先看错误就绪、执行时暴露的前置缺口、失效样本和未解阻塞，再看实际使用评价。回收字段、修订方式和分母见效果协议。

没有实际使用记录写“尚无使用记录”，没有评价写“未评价”；作者检查、演练和历史数据不冒充实际使用效果。查看不重新造数、不执行用例、不外发、不安排回访。
