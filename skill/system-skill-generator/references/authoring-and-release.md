# 创作、验证与发布

## 原子化先看目的

写“输入 → 关键判断或处理 → 输出”。一个目的可以有多个必要步骤、共享资源、自检及自己的效果查看。仅因步骤多就拆成碎片会增加使用负担；分析、设计、转换和执行的独立目的不能因都属于测试就合成一个skill。

明确触发请求、输入已知/缺失的处理、实际输出和结论边界。用户明确要求多个独立skill时分别交付并给衔接引用；明确要求编排器时按其范围编排，不伪称原子工具。

优先查已提供目录和已有成果，读取相关AGENTS、目标SKILL、元数据及版本记录；不扫描无关私有目录。更新保留适用名称、调用ID、用户改动、调用政策、依赖和历史，不能只重写入口忘记协议与例子。

## 可读与资源选择

标准最小包：

~~~text
skill-id/
  SKILL.md
  agents/openai.yaml
~~~

SKILL前置元数据含name、description；本规范新增技能含metadata.version。description说明真正用途和必要边界，不让它因为泛关键词吸引无关任务。正文说明版本、职责、关键工作、输出与效果入口。

UI显示名用用户指定中文名，内部ID小写英文、数字、连字符且小于64字符。default_prompt提及实际调用名。未请求图标、品牌色或依赖时不编造配置。

需要的才加：

- references：较长协议、特定模式、例子或验收场景；在入口写清何时读，不默认全读所有附件。
- scripts：重复转换/汇总或脆弱操作确需确定性实现才添加。使用者知道输入、输出、写入范围、错误结果和依赖。
- tests：新/改助手存在真实数据边界或统计风险时做有意义的隔离验证；不为纯文案机械增加镜像测试。
- assets：实际交付用的模板/素材；不是额外的指令副本。
- CHANGELOG：用户要求版本化，记录版本、日期、实际变化和迁移。

不复制第三方整套skill、历史业务资料、账号或生成时的运行目录。示例明确虚构，不能把作者自行跑过的演示写成真实用户反馈。

## 每个目标skill都要有最小效果方案

按目标职责设计：谁使用了哪个版本、哪里读不懂、哪一步准备/执行困难、结果能否独立判断、有哪些反例与误判、如何再次查看。这些内容可以是文档表格、已有记录协议或必要的本地助手，不必每次照搬本生成器的结构。

给一个可实际使用的“查看上次效果”请求或只读命令及记录位置，定义未评价、未使用、未核实。需要脚本却没提供时不能称查看能力已经可用；只定义人工查看也要说明读哪些记录、怎样汇总。

生成器只回收用户给出或授权读取的实际证据，不承诺自动收集目标环境数据。目标skill允许执行时，自己的权限、证据、错误恢复和停止边界要明确，不能由本生成任务代跑。

## 版本不是覆盖文件名

新建通常从1.0.0起。PATCH修正不改变行为的错误/表达；MINOR兼容新增能力；MAJOR改变职责、默认交付或不兼容协议。用户已有版本约定优先，说明采用依据。

版本来源在SKILL元数据；正文与CHANGELOG保持一致。skill版本、产物/目标业务版本、生成批次、反馈revision分开。修改先固定旧文件/仓库引用及哈希，保留差异和迁移；不复用已发布标签或覆盖旧版本包。

已有Git仓库依约定暂存本次文件并提交、打对应标签，不重置、不切用户分支、不夹带原有修改、不推送远端。没有Git且不需创建时，用版本目录、不可覆盖包和真实指纹仍可实现版本化。不要因工具不齐停掉有依据的创作。

维护源和安装目录分开，运行/反馈记录放项目或批次输出，不放skill安装目录。先核对安装副本，额外改动先比较合并，不默默覆盖。

## 验证层次与交付

| 层次 | 检查 | 能证明什么 |
|---|---|---|
| 结构 | frontmatter、UI元数据、ID、版本、相对引用 | 能被发现和读取，不证明决策正确 |
| 内容 | 输入输出、单一目的、边界、真实依赖、来源范围及示例 | 人工语义审阅，不能冒充独立外部验收 |
| 助手 | 隔离自测及适用冒烟，核对失败和空值/分母 | 对应本地脚本行为，不是目标业务通过 |
| 制品 | 包只有一个目标根目录，内容和版本与源码一致 | 制品一致性，不等于应用已加载 |
| 实际使用 | 有版本、场景、实际结果及证据 | 仅已使用范围的效果；未取得时留空 |

使用当前实际可用的创作校验器，先读其文档，不虚构命令。缺工具写未做及影响，可用已知能力检查相同结构，不凭缺某个检查器宣布业务失败。不可用的独立评审不写已完成。

打包排除.git、releases、缓存、依赖环境、测试临时数据、生成记录、密钥及业务私有附件。同步运行副本前完成必要验证；核对源码、包和运行副本，保留旧版及清理边界。仅要求源码或包时不额外安装。

交付说明结果、实际版本、调用方法、源/包位置、做过的验证和限制；别把计划写成已完成。生成记录记规则去向、产物、检查及后续反馈，协议见outcomes.md。
