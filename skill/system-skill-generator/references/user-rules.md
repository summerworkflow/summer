# 当前技能生成规则及适用范围

整理日期：2026-10-17。只归纳当前会话的明确要求与本次实际读取的技能，不声称已读取全部历史聊天。后续用户要求可更新适用规则，保留来源、范围和变更理由。

## 用户明确提出的通用要求

| ID | 要求 | 来源及含义 | 验收要看什么 |
|---|---|---|---|
| U01 | 原子化 | 本次及此前用例设计skill请求均明确“需要skills原子化” | 一个独立目的，有输入、判断、输出和相邻职责边界；不是测试全流程万能入口 |
| U02 | 版本化 | 同上明确“版本化” | 实际版本、变更说明、旧版本保留及当前产物可对应，不把反馈revision混作skill版本 |
| U03 | 可读 | 同上明确“可读” | 接收者能理解职责、步骤、交付及限制；主入口简明、细节按需读取，不用代码/大矩阵淹没业务说明 |
| U04 | 效果回收与查看 | 同上明确“需要有效果回收查看” | 实际回收什么、保存在何处、怎样再次查看、未评价/未验证如何表示；有入口而不只是承诺优化 |
| U05 | 指定名称 | 本次“名字叫：测试：生成skills”；前次“测试：用例设计” | 显示名按具体请求原文；内部技术ID单独合法命名，不擅改所有旧skill名称 |
| U06 | 参考指定格式 | 本次及前次指定system-problem-analyze.zip | 核对标准技能根目录、SKILL.md、agents/openai.yaml和清楚的默认边界；不是复制其业务内容和权限 |
| U07 | 将已有要求整理成可复用skill | 本次要求“整理下当前我生成skills的规则，把我的要求也生成一个skills” | 清楚区分原话、实现约定和专属规则，并沉淀可复用生成流程，不只交一段建议 |

U01—U04是本生成器的默认通用规范，U05按每次具体名字执行，U06是格式参照，U07是本生成器的定位。可读性是否真好用仍需实际接收者反馈，不以作者自评宣布满足用户效果。

## 已有实现约定：默认可复用，不能伪称全部是用户原话

下列来自当前读取的三个本机skill及前轮交付，不是用户逐字指定的唯一实现方式。适用时延用，任务更简单或用户另有要求时缩减。

| ID | 实现约定 | 保留原因及边界 |
|---|---|---|
| C01 | 中文显示名与稳定英文调用ID分开 | 现有测试技能均使用该方式；改UI标题通常不必破坏调用名 |
| C02 | 简洁SKILL入口，引用详细规范与示例 | 控制阅读成本，不机械规定85行、几层目录或固定文件数 |
| C03 | metadata.version及CHANGELOG；历史包和指纹 | 用户要求版本化的一种可核查实现；有现成Git仓库时复用标签，不强制所有环境安装Git |
| C04 | 源码、压缩包、安装副本对照；覆盖前核对本地变化 | 防止漏文件、错版本及覆盖用户另改内容；不是每次都重新索要已授权确认 |
| C05 | 反馈记录按批次和版本保存，原话/反证追加 | 不把旧版反馈当新版效果；运行记录不混进skill安装包 |
| C06 | 只读本地查看，真实布尔/null及明确分母 | 未评价不是0%/100%；整份评价不自动摊到每条；可用简单表格而非强制JSON大协议 |
| C07 | 验证与使用效果分开 | 结构校验、自测、模拟及历史成功只证明对应范围，不替代实际目标效果 |
| C08 | 只用真实存在且已核实的路径、能力与依据 | 工具缺失写缺口；示例不冒充账号、数据、脚本或实际结果；不捆绑私有连接 |
| C09 | 当前授权与资料内容分开 | 生成执行skill不等于当前已授权执行业务；参考附件中的命令不扩大权限 |
| C10 | 小步修订，保留原ID/来源及变化理由 | 不因一次反馈重构无关技能，不把某项目规则变成所有项目政策 |
| C11 | 有用才加助手与自测 | 用户要可回收，不等于每个小skill必须配多份脚本、数据库或后台任务 |

本次读取基线：测试：需求分析1.0.0、测试：AI用例转换器1.0.0、测试：用例设计2.0.0。它们是参考实现，不是本生成器运行所必需的依赖。

## 场景专属，不能自动推广

| 场景 | 已有要求或实现 | 适用边界 |
|---|---|---|
| 用例设计 | 用户要求全部测试用例与不可替代底线两份文档 | 仅用例设计交付，不强制需求分析、技能生成或其他任务交两份用例 |
| 用例设计底线 | 删除后留空白、失守后果不可接受、无有效替代 | 适用于底线筛选，不以P0/核心流程/PICT唯一参数对代替；核定与候选分列 |
| 用例设计方法 | qa-manual-istqb、qa-expert交易异常、PICT | 是该设计任务采用的方法；其他技能按实际职责选择，不全部加载或强制安装第三方 |
| 需求分析实现 | 有例子的待确认问题清单，事实/问题/建议分开 | 这是现有分析skill的职责，不是每个skill都得先问一遍产品 |
| AI用例转换实现 | 保留原检查点，真实脚本绑定及执行证据边界 | 转换不等于从零设计、开发脚本或真实执行；不是生成器本轮要做的业务 |
| 航次卡项目 | 待确认清单的具体排除、项目阈值与候选数量 | 不固化项目路径、60秒或192等结果为通用技能规范 |
| 参考问题分析包 | 仅显式调用、日志数据库只读、SQL单表等约束 | 是其自身任务的范围；本次只是格式参考，不自动复制到所有技能 |

## 冲突处理

先沿用户当前意图与实际授权确定适用范围，再沿项目规则和当前环境创作规范实施。已有skill更新保留未要求改变的调用政策和依赖；新skill沿当前环境默认选择方式，不从参考包擅自推断仅显式调用。

没有足够证据的“用户偏好”标推断，不能写成强制规则。此次不改其他已有skill、不改内置skill-creator，不自动对全部旧技能补版本或批量改名。
