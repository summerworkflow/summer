# 测试：生成skills

版本：1.0.0。历史见 [版本记录](CHANGELOG.md)。调用 $system-skill-generator。

## 职责

一项职责：把用户要求整理成一个可维护、可使用、可回收效果的测试skill，或修订该skill。效果查看针对本次生成及生成物的实际使用，不接管需求分析、用例设计、造数、执行和自动修复。

本轮只写获准的技能制品和生成记录。目标skill可以在用户指定范围内定义执行能力，但编写该能力不意味着本轮获准试业务、付款、赋权、查询生产或联系他人。已有授权适用时继续完成，不反复确认；新副作用按实际授权处理。

## 先区分规则范围

首次生成或整理规则时读 [用户规则](references/user-rules.md)。区分用户明确要求、已有实现约定、场景专属规则及未确认推断；新的适用用户要求优先，不把本文件当不可修改的个人政策。

通用核心：**原子化、版本化、可读、有效果回收且能查看**，名称和格式服从本次要求。原子化是一个独立目的，不是一行步骤一个skill；其必要步骤、校验和本任务效果查看可在同一skill内。

参考包只用于核对结构、表达和职责边界。保留SKILL.md及agents/openai.yaml的标准形式，按需要增加references、scripts、tests或assets；不照搬示例中的SQL、环境、禁止测试、仅显式调用等业务或调用政策。

## 生成／修订

1. **复用已知输入**：提取目标名称、主要输入和输出、边界、已有技能/参考包和适用版本。查看目标目录及项目约定，优先修订合适的已有skill，不创建重叠入口。不强迫用户填完整表格；只有真正影响结果的缺口才询问，明确部分继续。
2. **定一个目的**：用一句话写“输入什么 → 做什么判断/处理 → 输出什么”。区分相邻能力和被排除的动作；多独立目的拆开或按用户明确要求编排，不把测试全流程塞进原子skill。
3. **写可读入口**：主文件保留职责、触发、关键步骤、证据边界、交付及查看入口；详细协议、示例和条件流程按需链接。说明具体行为，不堆“全面、专业、正确”等空话，不硬设行数或文件数。
4. **建立版本与回收**：先读 [创作与发布](references/authoring-and-release.md) 及 [记录与效果](references/outcomes.md)。版本、变更、批次、反馈修订分开；每个目标skill有适合其职责的最小反馈内容和可操作查看方式，不能只写“后续持续优化”。
5. **验证后交付**：核对结构、引用、触发边界、真实依赖和行为例子。新增助手时做必要隔离自测；本地结构检查或自测不是业务通过和真实使用效果。按 [行为场景](references/acceptance.md) 处理易错边界。
6. **发布并记录**：核对源、版本包与安装副本的一致性，保留旧版和修订理由；按本次范围安装或只交包，不改无关skill及全局配置。记录真实验证和未做项；未得到反馈的字段保留空或null。

若当前环境有适用的技能创作工具/规范，读取实际入口再使用；不存在时依本skill完成，不虚构工具或要求安装固定框架。此skill不递归调用自己来再创建一个生成器，不改内置skill-creator。

## 必须可审阅的交付

- skill源码和实际调用名，UI显示名按用户原文；内部目录名遵守小写英文、数字及连字符约定。
- 明确版本与CHANGELOG，版本包保持历史可定位；Git可用时按现有仓库约定提交及打标签，否则保留不可覆盖的版本快照和指纹，不因缺Git拒绝。
- 任务有关的验证结果、限制、安装状态与必要迁移说明；不给未执行项打通过。
- 项目输出目录的一份skill-generation-record.json，关联需求、规则去向、产物和后续反馈；它不放进目标skill安装包。小型目标skill可用可读表格回收，不强制每个技能复制这套JSON或汇总脚本。

打包只含目标skill根目录；不附带.git、运行记录、缓存、依赖环境、账号或私有业务资料。用户只要聊天或源码时按其要求缩减交付，不为了模板制造无用文件。

## 效果回收与查看

用户要求“查看这次生成是否符合要求”“这个skill好不好用”时，读取明确指定的生成记录及获准实际反馈，使用 [效果协议](references/outcomes.md)。不重新生成、不开始试业务、不自动发问卷或创建回访。

查看先列未满足要求、未做检查和真实使用问题，再分开显示：

- 生成质量：是否职责清楚、表达可读、版本一致、查看入口可用。
- 生成物的目标任务效果：仅依据实际目标版本的使用记录，区分报告、待核实及已验证。

两者不能混算。没有实际反馈写未评价，没有使用记录写尚无使用记录；无可比前后基线不称节省时间。结构通过、自测、技能数量和文件数量都不是有效性得分。

本地只读查看助手，脚本路径解析到本skill实际目录，记录路径换成实际值：

~~~powershell
python -X utf8 scripts/review_generation.py "生成批次/skill-generation-record.json"
python -X utf8 scripts/review_generation.py "批次A/skill-generation-record.json" "批次B/skill-generation-record.json" --format json
~~~

回收追加来源和历史，增加revision，不抹旧评价。生成物逻辑或版本变更另建生成批次，不借旧版通过或评价。改进先列有依据的提案，用户要求应用时再修改并升版；当前请求已授权的修订直接完成。
