# 评审效果回收与查看

使用可读的 用例评审反馈.md，收到查看请求时由AI读取指定报告与记录后汇总，无需额外脚本或后台采集。

## 初始化记录

记录 run_id、revision=1、system-testcase-review/1.0.0、报告路径和实际指纹、源用例及规则版本、RV编号及前批次映射。作者检查单列；实际使用和反馈未取得时写“尚无使用记录”“未评价”。

每项发现跟踪：未处理 / 已采纳待改 / 已修订待复核 / 复核关闭 / 误报撤销 / 重复合并 / 待裁定。保留处理依据、对应源版本、关联用例及当前下一步。采纳不是发现已证实，修订不是复核完成，复核关闭不是产品已测试通过。

## 真实事件

每条事件包含事件编号、带时区时间、skill版本、评审批次、对应报告指纹或精确版本、关联RV/用例或“整份”、来源定位及实际原话。

按实际内容记录以下评价：问题是否成立、定位是否准确、建议能否用于修订、表达是否易懂。评价为满足/不满足/未评价；整份“有用”只保留整体原话，不分摊到全部问题和维度。反对意见保留其理由，不能不经核对就记误报。

后续证据可记录：真实漏审点、实际误报、错误定级、采纳/修订/复核过程及下游使用困难。缺陷事件是否原可发现需有适用版本、规则和用例的因果核对，不能看到后来Bug就反推本次必然漏审。

## 查看入口

用户可说：“查看这次用例评审效果，报告和反馈在……”。只读明确指定的文件和获准证据：

1. 核对报告、源基线、skill版本及批次；不同版本分别展示，不混算。
2. 先列未关闭重要发现、误报争议、真实漏审及依赖缺口，再展示处置和使用情况。
3. 同对象/维度按时间最后的实际评价显示，显式未评价可撤回当前判定；全部历史和反证保留。
4. 需要统计时报告原始条目数，处置状态与实际评价分开。评价分母只包含该对象该维度的真实非空评价，不用发现总数或重复事件作分母；无分母不报0%/100%。
5. 提出针对具体偏差的改进及反例。没有比较基线不声称节省时间、减少漏测或提高业务质量。

新增反馈先核对并发变化，保留旧revision快照再追加；修改源用例、依据或评审判断后建新批次，保留RV映射。查看不重新设计、执行、外发、找人评价或安排回访。

技能结构校验、作者演练、评审发现数量和问题关闭率均只支持相应事实，不能直接当实际使用效果。维护skill按用户授权处理并升版，不把某项目口径自动变成所有项目的通用规则。
