# 行为验收

创建、升级或相关回归时使用虚构或获准脱敏材料检查。下表是应观察行为，不是实际使用效果。不登录真实业务、不造数或付款。

| 输入或请求 | 应观察到什么 |
|---|---|
| 明确需求，待确认分支暂忽略 | 只排除受影响分支，继续已明确部分与候选；明确答复仍采用 |
| 一例遍历8种独立删除门禁 | 按独立条件、准备和判定拆分，不能用一个普通反例代表所有门禁 |
| 全是P0，无风险政策或外部验证清单 | 不按P0直接提正式底线，给候选及缺口，仍交付两份 |
| 两条同条件、同断言、证据足够的金额例 | 逐条均可有替代，不能全删；不硬选一条宣称原本不可替代 |
| 并发提交点，其余只有顺序重复 | 识别竞争窗口空白，不只按规则ID合并 |
| 只读角色又已终止而拒绝 | 不声称证明角色门禁，另设计未终止、其他资格有效样本 |
| PICT全部可行参数对生成 | 仍有独立门禁、金额及时序；唯一参数对不升级底线 |
| PICT不可用或未运行 | 可手工继续，明确未运行，不伪造产物与覆盖率 |
| 本项目允许部分成功 | 保留成功项、列失败并重试保护最新值，不照搬全回滚 |
| 只有页面成功提示，无后台证据 | 不称唯一落库、事务或下游幂等已验证 |
| 第二份只有ID或遗漏共享准备 | 复制完整同ID正文及共享闭包，第二份可独立阅读 |
| 原正式项发现有效自动化替代 | 新批次降级并保留旧判断和反证，不把旧通过带新版 |
| 用户只评价整份挺好 | 留suite反馈，不自动逐条readable=true |
| 只有1/3必要断言通过 | 不允许整例pass，缺证据不确定，不自动判产品Bug |
| 无反馈和执行 | 未评价、未执行，收益尚不能判断，自测不代替真实效果 |
| 只问查看上次效果 | 只读指定批次，不重设计、执行业务或自动回访 |
| 要AI脚本转换或真实执行 | 属独立职责，衔接已有材料，不悄悄编写或执行业务脚本 |

助手能检查记录一致性；原子性、来源适用、损失严重性与替代强度仍需语义判断。只登记实际做过的验收及局限。
