# 设计方法、交易异常与PICT

只沉淀方法，不依赖安装第三方skill，不继承其自动执行、固定指标或环境配置。方法不是项目正向业务规范。

## ISTQB方法落地

| 材料特征 | 方法 | 留下什么依据 |
|---|---|---|
| 同类输入应同处理 | 等价类 | 合法/非法分区及代表值，不把不同状态路径当等价输入 |
| 上下限、精度、日期、时限 | 边界值 | 边界、相等、邻接值与单位，只用已确认阈值 |
| 条件共同决定权限或动作 | 决策表 | 条件、动作、可达列、拒绝优先级和单门禁反例 |
| 行为依赖历史/当前状态 | 状态迁移 | 合法/禁止转换、恢复、重复及必要转换序列 |
| 多入口、多对象或上下游 | 业务场景 | 主流程、替代/失败路径、稳定身份和各段采用的数据 |
| 已知缺陷或薄弱点 | 经验检查 | 实际暴露条件和健康对照，预期仍追溯正式依据 |

风险驱动投入：具体错误 → 直接后果 → 条件与暴露面 → 现有防护/验证 → 用例及证据。场景和来源变化时更新，不把初始风险分析做成一次性表格。沿用项目优先级，不复制第三方固定P0比例、用例数量或覆盖率。

## 交易、保存与恢复

只选择本项目真实涉及的轴，不给纯查询模块硬加支付异常。

| 失败轴 | 准备与断言 |
|---|---|
| 提交前失败 | 已存金额、状态、关系和成功记录不变，输入及重试按项目规则 |
| 部分持久化失败 | 先确定整组原子还是允许部分成功，逐项核对成功/失败范围，不套统一全回滚 |
| 外部已受理、本地失败或响应未知 | 原对象/原操作标识/金额/币种/接收方保持，先查原结果再按现有规则恢复，不能盲目重建 |
| 重复点击、重投或补偿 | 同次效果不重复，合法第二次业务不能误判成同次重试 |
| 旧页面、旧任务晚到 | 提交点改变版本、人工值、终态或退款资格，旧动作不得覆盖新事实 |
| 恢复或队列阻塞 | 漏处理可按明确条件补扫，异常对象不阻断健康对象；未知容量/时限不发明SLA |
| 下游失败 | 上游提交与下游效果分查，补偿修复原对象，不新增重复资金/库存/事件 |

写出失败位置、参与者、时序、同步屏障、同次请求或新业务及最终检查点。所需故障注入或后台能力未落实时标待准备，不以页面超时证明服务端未提交。选择相关健康对照，防止“一律拒绝”的实现看似正确。

## PICT组合

1. 先确定规则、因素、可达值与约束。重大门禁独立反例、金额算例和竞争时序先设计，组合补交互。
2. 保留模型、实际PICT版本/命令、模型与输出指纹、生成行号到用例ID的映射及预期推导。
3. 约束排除不可达状态，不能为减少数量排除需要被拒绝的可达请求。模型合法组合和业务可接受输入是两回事。
4. 多非法条件可能遮蔽门禁，每个重要拒绝条件还须其他资格有效的单独反例；“只读＋终止”不证明角色拒绝。
5. 改因素/约束或删输出行后重新核验可行参数对、每行可达性及遗漏。没有独立的可行组合依据时不宣称已证全覆盖。
6. 二因素覆盖不证明状态序列、三因素风险、事务或全部业务。高阶风险有据补例或提高阶数，不机械全项目三因素。

PICT已核实的命令形状为 `pict model.txt /o:2`，实际使用核对当前可用版本文档。以下模型仅为虚构语法例子：

```text
Business: VC, TC
Role: OP, READ
State: RUN, STOP
Action: Edit, VcTime
IF [Action] = "VcTime" THEN [Business] = "VC";
```

无可用PICT可继续手工决策表/组合设计，标明未运行PICT。枚举规模超资源时注明核验上限和待核部分，不以抽查当全覆盖，不称手写行是PICT产物。
