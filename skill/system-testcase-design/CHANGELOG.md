# 版本记录

## 2.0.0 — 2026-10-17

显示名改为“测试：用例设计”，调用名保留system-testcase-design。职责仍限设计、修订及本设计效果回收，不接管执行、真实造数、脚本转换或完整QA编排。

| 方面 | 1.1.0 | 2.0.0 |
|---|---|---|
| 默认交付 | 一份Markdown | 全部用例与不可替代业务底线两份可读文档，另有索引反馈记录 |
| 方法 | 通用场景与风险 | 明确ISTQB方法、qa-expert交易异常、PICT组合及其边界 |
| 原子性 | 一个主要目标 | 强调独立门禁、条件遮蔽和参数行独立统计 |
| 底线判定 | 无单独判定 | 删除空白、不可接受后果、无有效替代三条件；正式/候选/有替代/非底线/未评估分列 |
| 双文档一致 | 不适用 | 唯一正文源、同ID指纹、共享依赖闭包、不覆盖历史 |
| 效果回收 | 无本地协议 | 按批次及版本回收实际评价、执行证据、误判/漏项与收益基线 |
| 工具 | 无助手 | 只读校验/查看与第二文档生成；隔离虚构自测 |

默认交付和记录方式不兼容，故升主版本。记录协议从1.0起，与skill版本、用例版本和revision分开。

迁移：旧文档和旧ID保留，不自动改旧结果。用户要求修订时读取旧依据及范围，建立新design_id、previous_design_id及两份交付；旧执行/反馈不当新版结果。航次卡的192候选数及具体时限不固化为通用规则。

验证：skill结构、相对链接、助手隔离自测及CLI生成—校验—查看；语义按行为场景人工核对。结果留维护仓库releases，不冒充实际用户反馈或业务通过。

## 1.1.0 — 2026-10-16

增强用例设计阶段的前置条件与数据准备交付，继续只设计方案，不自动真实造数。

| 方面 | v1.0.0 | v1.1.0 |
|---|---|---|
| 单条用例前置 | “前置与数据”合并说明，要求状态、权限和合法准备链 | 分成“前置条件”“测试数据引用”，逐条关联并允许共享前置加差异 |
| 需要什么数据 | 原则性描述关键数据，无统一清单 | 明确对象、状态、关键约束、关联关系、用途及逻辑数据 ID |
| 需要多少数据 | 提到独立和重复执行，未规定数量分配表达 | 说明每例／参数组／每轮数量、共用或独占、消耗及复用条件 |
| 数据怎样准备 | 要求合法准备路径，可引用已有流程 | 新增有序准备链，逐步交代角色、输入、依赖、输出和完成检查点 |
| 什么时候算准备好 | 区分设计状态与准备状态 | 增加数据方案完整性判断和实例核对要求，关联缺口与受影响用例 |
| 示例 | 并发付款的前置描述及断言 | 增加三组数据清单、数量计算、共享同一目标和三步造数方案 |
| 版本追踪 | 首次交付时未写版本号 | SKILL.md 的 metadata.version 为版本号来源；Git 标签、版本包和本记录保留历史 |

新增 [前置与数据准备设计](references/data-preparation-design.md)；同步修改主流程、用例契约、示例及界面提示。场景设计方法沿用 v1.0.0。

已有用例修订时，将原“前置与数据”拆分或映射为新版两项语义，共享内容引用数据清单；不会自动重写历史用例。
