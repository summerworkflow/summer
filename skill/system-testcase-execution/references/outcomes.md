# 执行效果回收与查看

执行效果反馈.md保存在项目批次，含run_id、revision、skill/版本、台账及人工记录路径和指纹、用例/规则/部署基线。作者检查与真实使用分栏；无记录写尚无使用记录，无评价写未评价。

## 回收什么

每个真实事件记事件ID、带时区时间、技能版本、run_id/记录revision或指纹、用例/分支/断言/attempt或整份、真实使用范围、观察或原话、来源定位、处理状态及后续动作。实际Bug、执行断言不符、准备/脚本问题和接收者对skill的评价分别保存。

回收重点：错误通过/失败、漏执行或错范围、错误对象/身份、证据不足、首次失败被覆盖、未知写入误重放、回归遗漏、阻塞恢复是否有效、交接是否可追溯及意外副作用。每项需核对适用版本和因果；后来Bug不自动证明本次漏测。

评价维度按真实答复为范围准确、结论有据、可恢复、交接易懂；值为满足/不满足/未评价。整份“好用”只保存原话，不分摊给每条用例或维度。实际用例通过率、缺陷数量、执行时间和检查器通过均不是skill有效性评分。

问题用FB编号，状态为待核实 / 已确认待处理 / 已修订待复核 / 复核关闭 / 反证撤销 / 待裁定。修订和复核保留关联证据；接受建议不等于证实问题，业务Bug修复不自动等于skill修复。

## 查看入口

用户可说：“使用 $system-testcase-execution 查看这次执行效果，台账、执行记录及反馈在……”。只读指定资料和获准证据：

1. 核对run、技能/用例/规则/部署版本、原始记录和指纹。若用检查器，说明它只校验声明台账且不读证据内容；它的结果不是实际系统复测。
2. 先展示错误通过、漏项、未知副作用、未解阻塞、未决证据及反证争议，再列首轮/重试/回归的实际处置和接收者评价。
3. 同对象/维度按时间最后实际评价展示，显式未评价可撤回；保留全部历史。需要计数时按明确对象去重，分母仅含真实非空评价，不拿尝试总数或所有用例数作满意率分母；无分母不报0%/100%。
4. 不同技能、需求或部署版本分别展示，不把旧环境成功并到当前覆盖。没有实际使用/反馈保持空，不从作者自测推断。
5. 有具体反例才提改进；无可比前后基线不称提效、减少漏测或提高质量。查看不重新执行、联系他人、外发、发问卷、改源用例或安排回访。

反馈追加前核对并发修改，保留旧revision快照再增加revision。已完成attempt的观察不得用重试结果覆盖；纠错追加说明及来源，保留原结论。业务基线变化建新run，skill逻辑变化另升版。用户已授权修订时完成对应修改，否则只列可验证提案，不自动改共享知识或skill。
