# 实际执行与恢复

## 先核实对象和权限

从当前可观察事实核对环境、组织/租户、身份/角色、对象稳定ID、业务类型、方向和初态；看不到的写未知。指定业务对象是范围锚点，定位失败不能用另一条记录顶替。已有数据默认只读，当前目标/动作授权适用时才修改。

复用前置交接的DATA/CAP编号，实际再看样本及易变状态。用例、预期或部署变化须重核适用性；旧证据仅作历史。准备练习与正式测试分开，不能用一次试运行回填全部正式用例。

业务造数使用合法链和可识别测试标记，捕获实际ID、归属及父子关系。变更、消耗、删除/作废样本按分支和轮次分配；删除/作废用例用专属合法源。Bug可能污染样本时隔离后续用例并保留原现场。并发类按原设计保留同一竞争目标，不为隔离破坏待测条件。

脚本使用前核实真实入口、参数、版本/依赖、环境、输出、副作用和失败传播；历史绑定不是当前可用性。准备接口不能代替原用例要求验证的UI动作。工具缺失时只阻塞依赖它的检查，不假设存在框架，也不为凑执行改用例渠道。

## 一次尝试怎么执行

1. 给本次attempt稳定编号，记录时间、来源基线、对象/父对象ID和DATA编号；写前记录动作意图、输入、初态及预期副作用。
2. 核对本例独立预期及证据层。金融计算列公式、操作数、币种、符号、精度和舍入规则；显示值不能反向成为预期。
3. 按原用例步骤实际操作。每次有后果动作后先核对结果，不批量盲点后再猜发生了什么。
4. 分别比较每个必要断言，捕获即时结果、对象标识和所需回读/刷新/重入；一次成功提示不能覆盖所有断言。
5. 保存创建/修改对象、失败状态、已确认副作用和仍未知部分。保留网络证据可得性；未取到不编造请求次数、业务码或链路。

测试的故障条件必须维持：负例的无效附件、角色或金额不能被“修复”；此类用例的前置核实是确认指定无效条件与其他条件，而不是要求被测动作必定成功。

隐藏层断言（事务原子性、唯一扣款/消息、后端幂等等）需要相应授权且足够的独立证据。只有页面结果时，记录可见断言，隐藏断言仍blocked/inconclusive；不得把整条全层用例写passed。用户明确只选UI验证时保留缩范围依据和残余检查。

## 状态和问题分类

- passed：本断言的适用预期、实际操作和充分证据一致；分支/用例通过还需全部必要项满足。
- failed：合法前置下，实际证据反驳独立预期。准备、定位或脚本错误不能直接判产品失败。
- blocked：缺前置、权限、可达状态、预期裁定或必要证据能力，写精确缺口及影响。
- inconclusive：动作发生但观测矛盾、结果未知或证据不足，写未能判断的内容与停止原因。
- not_run：尚未尝试/尚未处置；未选项另在范围记录，不混入所选项通过率。

步骤失败后，仅对确实依赖失败步骤的后续断言写blocked并解释依赖，不能为了收口把所有not_run机械改blocked。独立断言仍需执行。failed与确认Bug分开：核对规则、数据、脚本、环境并完成适用证据审查后才可确认；不自动从一个错误提示推断根因。

## 写入不明、重试和恢复

超时、断连、重复提示或脚本异常时先保留首轮输入、错误、对象标识和写前意图。按稳定业务标识只读查证：确认未发送/未落地才在原授权内继续；已经生效则复用事实，不重建相同数据。无法判断则停止依赖路径，不盲点、换号、重登后重放或清理现场。

若重复提交本身是选定测试，按其参数和授权有意重发，仍记录每次请求/动作与副作用；不能用一般恢复逻辑掩盖重复条件。实际点击、可捕获请求和已验证对象数量分列。

恢复先读全部attempt及成功造数；新attempt关联同分支最近一次attempt，写重试原因、已核实状态、差异和证据。每次尝试完整给出该分支必要断言的本次结论，不把不同尝试各自通过的断言拼成一次通过。

同一故障无新信息、身份或归属不明、继续可能叠加副作用时停止该路径，独立工作继续。修复脚本/定位后按当前授权验证，不因技术路径变化重复索要已有权限。新环境、部署或规则基线单独建run，保留前run链接。

## 等待、回归和初始阻塞复查

异步状态先明确合法产生方法、适用等待规则、轮询间隔和总时限；优先项目已确认约定，不能虚构业务SLA。仅记录有意义状态变化。到时限按需求规定的超时预期判断；规则未定或无法观测则blocked/inconclusive，不无限等待或猜已完成。

首轮先遍历全部选定分支。固定回归取已约定且适用清单；动态回归来自本轮失败、状态/金额/权限风险及变更影响，记原因、对象、断言和执行结果。无固定或动态项需给可核对理由，不以空列表自动证明无风险。

首轮后的初始阻塞复查逐项记录：已解除并实际重试、仍阻塞且有新核对证据、或明确人类授权取消。若无新信息或未获写入授权，复查记录即可，不能为了“一次重试”重复危险动作。重试成功保留首轮阻塞/失败；后续新缺陷仍进入适用回归。

## 结束边界

所选用例、分支和断言不能无说明漏掉；未执行项保留not_run并如实报告执行未完成。记录可在仍有失败、阻塞或未决时收口，但必须明确范围、原因、后续动作及未知副作用。“台账已收口”不等于业务通过、缺陷修复或可发布。

保留首轮与各尝试、数据残留及证据。清理、缺陷提交、外发或风险接受按当前授权单独处理，不把收尾当自动破坏现场或上线的理由。
