# 脚本绑定、准备检查与失败边界

## 一个可复用入口应说明什么

| 项目 | 绑定要求 |
| --- | --- |
| 身份 | 能力ID、实际路径/仓库、版本或哈希、入口函数或已有CLI |
| 适用条件 | 业务分支、环境/部署、角色、初始状态和已知限制 |
| 参数 | 名称、合法值/约束、来自固定用例参数还是上一步返回；不填凭据 |
| 返回 | 实际对象ID、父子关系、状态/数值和失败信息；说明哪些供后续调用 |
| 环节 | prepare、act、check中的一个或多个；可由同一入口实现多个环节 |
| 副作用 | 创建/修改哪些对象、是否一次性消耗、是否触发付款/通知/审批 |
| 断言和证据 | 检查什么、从哪里读取、失败是否明确传播、证据位置 |
| 验证情况 | 未验证、历史验证、当前目标环境/版本验证；保留证据和适用范围 |

不能看到文件名含“create”就认定它能造出本例状态；不能因某分支成功，就认定其他币种/业务类型/权限组合也可用。

## 原用例、脚本和数据怎样接起来

每个调用都给稳定调用编号；写明输入来自哪个用例参数、哪个准备输出，输出ID交给哪些动作/检查。不把临时示例ID写成可执行实例。

准备结果至少核对本例所需身份、归属、状态、关键数值和关系。用正常业务链准备的数据，不通过直接改库、跳审批或伪造状态来替代；用户明确要求隔离/故障注入时，另标验证范围和省略环节。

脚本化路径的可用性按当前证据判断：

- 路径/接口说明存在：可以编写调用计划，不等于已运行。
- 历史证据存在：说明旧环境适用条件，当前仍须核对。
- 当前环境/部署和本例分支已有验证：记录具体证据；本轮实际数据仍须执行前检查。

“脚本方案已绑定”不要求样本现在已经创建；此时准备状态可以是未核实。只有实际前置和全部必要能力已有匹配证据，才标“已核实就绪”。

## 可减少的探索

已知入口、字段定位、参数、对象ID、计算依据和检查方法写进制品并复用。缺稳定定位时列出具体缺哪一个控件或对象，不把“让AI自己找”当完成转换。

首次走通任务需要写清：目标入口、最小样本、允许探索范围、应产生的可复用能力、成功检查、停止条件。转换器只提出任务，不默认执行。没有用户授权时不远程派发。

后续执行失败时优先使用已有日志、回读和证据定位阶段。只有出现新信息且仍在授权内才调整尝试；重复同一失败不无限循环、不悄悄换对象或换预期。

## 失败分开记

| 发生了什么 | 分类与后续 |
| --- | --- |
| 账号/数据/状态不满足 | setup_failed：准备失败，说明缺哪个条件 |
| 定位、调用参数或脚本异常 | script_failed：脚本/操作失败，保留错误及执行到哪一步 |
| 操作已生效，实际值不符独立预期 | assertion_failed：断言不符，保留实际/预期及依据，进一步核实 |
| 规则冲突、依赖或证据能力缺失 | blocked：注明仅阻塞哪些检查 |
| 必需前置、动作及全部必要断言均有实际证据 | pass：仅对记录中的环境/版本/对象和观察范围成立 |

退出码0、HTTP成功、弹出成功提示，均不能代替必要断言。检查失败须在调用约定中明确传播，不能吞掉异常后继续汇总为通过。

记录第一次尝试与重跑，不只保留最终成功。写操作超时先按稳定ID回读；无法确定结果时停止该分支并说明，不盲重试。
