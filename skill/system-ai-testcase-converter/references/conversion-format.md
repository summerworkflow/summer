# 转换格式与示例

## 原用例对应表

| 原用例ID/位置 | 原检查点 | AI用例ID | 处理方式及原因 |
| --- | --- | --- | --- |
| 原文可定位位置 | 保留原意思的检查点 | 稳定目标ID或待补项 | 拆分、合并、保留人工、待补或有据排除 |

拆分后检查原条件、动作、结果及副作用是否均有去向。不能为了容易自动化只留正常流程；重复检查点可合并但仍保留原ID对应。

## 每条AI用例需要表达的内容

| 内容 | 写到什么程度 |
| --- | --- |
| 编号、标题、原用例 | 一个主要验证目标，能回查原步骤和检查点 |
| 正确结果及来源 | 适用业务依据；未知预期明确待确认，不抄被测代码结果 |
| 前置与数据 | 环境/角色、对象状态/关系、数值、每轮数量、共享/独占及标记 |
| 准备调用与检查 | 实际入口/参数来源/返回ID；回读确认准备到了动作前 |
| 被测动作 | 对哪个对象做什么；测试页面时保留页面动作 |
| 逐条断言 | 触发步骤、实际观察位置、独立预期、判定和证据 |
| 失败与重跑 | 哪阶段失败，在哪里停止，怎样先核对不明结果，数据怎样隔离 |
| 设计与准备状态 | 清楚写缺什么；示例不是实际就绪实例 |

共享入口可集中说明，单例引用具体参数；不把整段公共说明复制到每一例。

## 完整的虚构转换示例

以下业务规则、数值、脚本能力均为说明写法，不是其他项目的通用规范，也不表示存在相应脚本。

**人工原用例 MAN-01：** 检查数量计费、包干计费和人工运费保护，结果应正确。

先拆成三个主要目标：数量计费、包干计费、人工运费保护。原文“正确”不足以确定答案，必须查到适用依据后才能填写正式预期。

假设本次获准依据R-20明确：“数量计费初值为数量×运价；人工修改运费后，数量变化及保存不能覆盖人工金额。”下面仅示范人工运费保护这一条，其余两个目标仍要分别有去向。

### AI-MAN-01-03：改数量并保存后，人工运费保持原值

原对应：MAN-01中“人工运费保护”；依据：本示例R-20。

前置与分配：

- 目标版本支持该规则，当前角色有草稿编辑权限。
- 每轮本例独占一张未锁定的VC租出卡、一条数量计费货物；不依赖上一例的数据。
- 初始数量10,000，运价20 USD，系统初始运费200,000 USD；经正常人工编辑改为180,000 USD并保存。
- 准备入口需要返回本例card_id、cargo_id和回读数值，确认是这张卡的这条货物，已保存数量10,000、运价20、运费180,000。

调用计划：

| 顺序 | 所需环节/能力 | 输入 | 返回及检查 |
| --- | --- | --- | --- |
| P1 | 准备人工运费草稿 | 本轮标记、业务类型、数量10,000、运价20、人工运费180,000 | 返回card_id/cargo_id；重进核对初始值 |
| T1 | 页面修改指定货物数量 | P1返回的ID、数量12,000 | 数量实际改为12,000 |
| C1 | 读取同一货物 | 同一组ID | A1：运费仍180,000，不变成240,000 |
| T2 | 保存草稿并重新打开 | 同一张卡 | A2：数量12,000确实持久化；A3：运费仍180,000 |

具体脚本文件、入口、调用模板及版本：本示例未绑定，实际转换时从真实目录填入；不能把上表的能力名称当作已存在的函数或命令。

证据：目标对象ID、初始回读、改数量后的数值、保存重进后的同一对象数值。仅凭“保存成功”不能通过；未确认数量改变时也不能通过。

失败处理：

- P1找不到对象或初值不符：准备失败，停止该例，保留准备证据。
- T1没有改动数量或定位错误：脚本/操作失败，不把金额未变当通过。
- 数量已变而金额变为240,000：断言不符，保存对照证据，待核实；不自动修改预期。
- 保存超时且结果不明：先读取同一对象确认保存结果，不盲目重复提交。
- 重跑按本例分配新的独占样本，失败现场不清理；清理按项目已有规则另行处理。

设计：按本示例规则已明确。路线：首次需走通。准备：未核实。执行：尚未执行。若实际材料没有R-20，则应改为等待规则确认，不能采用本示例金额保护规则。

## 行为验收场景

创建或升级时逐项自审；这些场景不代表实际用户反馈。

1. 原例含三个独立目标：三个目标均映射；不只转换最容易的一条。
2. “应正常保存”没有适用规则：保留待确认，不能从保存方法推导预期。
3. 远端脚本只有文件名：标未核实，不编出命令或标已就绪。
4. 测试新建：准备脚本不能先完成新建；测试页面：接口只能用于相应准备或辅助取证。
5. 人工金额保持：同时检查触发字段确实变化，保存后回读同一对象。
6. 一脚本包含准备/操作/检查：保留内部阶段与断言，不强制复制成三个文件。
7. 超时结果不明：先核对、保留现场；不自动重放写操作或改预期。
8. 只有转换文档没有运行证据：显示尚未试跑；不生成通过率或省时结论。
9. 用户只说“整份看不懂”：记录整体反馈，不把所有单例伪造为逐题评分。
10. 用户只要转换：不顺手写业务脚本、造数据或执行测试。
