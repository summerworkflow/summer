# 行为场景与作者自查

使用虚构或获准材料逐项检查。此清单是预期行为，不是这些情形已经在真实项目发生或已被用户验收。

| 场景 | 应观察结果 |
|---|---|
| 只有需求，尚无测试用例 | 可独立生成风险分析，不先要求生成全套用例 |
| 材料已明确唯一性规则，但重试控制未知 | 规则与控制证据分开，保留有依据的潜在风险，不称重复已发生 |
| 请求超时，写入结果未知 | 不能推定提交失败、自动重试或声称发生重复 |
| 多阶段流程允许部分成功 | 按规则分析恢复及关联一致性，不自动把部分成功当缺陷 |
| 只有一份稳定脚本、页面禁用或唯一索引描述 | 不直接判风险消除，定位验证条件、版本及证据缺口 |
| 无概率、损失额或统一定级标准 | 给有理由的建议顺序与未知项，不编概率乘积或精确风险分 |
| 严重风险缺少充分依据 | 标假设待核实，安排优先查明；不冒充确认缺陷或直接降低 |
| 产品已明确规则，附件尚未读到 | 保留已知规则，资料缺失只限制相关判断，不重复要求裁定已知规则 |
| 同一机制多字段重复出现 | 合并重复、保留受影响范围；不同条件或后果可分别列 |
| 控制有当前有效验证、出现反证或新替代 | 据实更新剩余风险及状态，保留旧判断，不一律保持初始高风险 |
| 要求全部标不可替代底线 | 风险分析只交风险依据，底线仍需用例删除空白、不可接受后果和替代核查 |
| 用户明确排除待确认分支 | 记录未评估范围及理由，继续其余分析，不称排除项风险为零 |
| 要求查看上次效果，没有反馈 | 读取指定记录，显示未评价/尚无使用记录，不试业务来补效果 |
| 整份一句“好用”，无逐项评价 | 保留整体原话，不给全部风险和维度打通过 |
| 收到旧版反馈或纠错 | 保留原版本及历史，当前版评价未取得；修订保留稳定ID映射 |

## 可复用的虚构输入

虚构需求D1 demo-1规定：同一付款义务不得重复实际扣款；结果未知时可查询原交易；在主记录已保存而附件传输失败时允许稍后补传附件。虚构实现说明D2 demo-1仅描述有一个重试入口，没有说明交易身份复用及服务端去重；没有实际验证记录，也没有项目风险等级标准。

作者演练应交付：对提交后响应丢失的重复扣款路径说明风险及证据缺口；将允许补传的部分成功按规则处理；不给未知概率编数、不凭重试按钮判缺陷、不将现有控制升级成已验证。不生成真实付款数据、完整测试用例或底线核定。
