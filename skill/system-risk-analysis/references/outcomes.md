# 风险分析效果回收与查看

本技能采用可读 Markdown 记录，由收到查看请求的 AI 读取并按本协议汇总，不依赖额外脚本。记录只保存本次分析索引和真实反馈，不复制完整风险正文。

## 初始化《风险分析反馈.md》

~~~markdown
# 风险分析反馈

- run_id：本次唯一批次
- revision：1
- skill：system-risk-analysis
- skill_version：1.0.0
- 分析文件：本次业务风险分析的实际路径/定位
- 分析文件SHA-256：实际可计算时填写，否则未取得
- 材料基线：本次实际版本及来源索引
- 风险编号：本次实际RISK编号及前版映射
- 作者自审：实际完成范围及未核实项，单列，不能当接收者评价

## 实际反馈事件

尚无反馈，未评价。

## 实际使用记录

尚无使用记录。

## 已提出的改进

暂无。
~~~

模板中的示意文字在创建真实批次时替换为实际值；不知道写未知，不伪填“通过”。记录保存在项目输出，不能写进 skill 安装目录。

## 追加事件

每条真实反馈保存事件编号、带时区时间、适用 skill/分析批次、分析文件指纹或精确版本、关联风险ID或“整份”、反馈来源定位和原话。

按实际内容选择维度：可读性、判断依据、优先级合理性、交接可用性。评价为满足/不满足/未评价，不把一句“好用”分摊成所有维度通过。可同时记录遗漏、误报、过度定级、错误降级或控制误判，保留反证及后续处理状态。

实际使用另记谁在什么任务、哪个版本使用了分析，影响哪些设计/评审/决策，观察到什么、证据和限制。采纳建议不代表风险已验证或消除；执行结果只能引用真实证据。

旧事件只追加，不删除；纠正时加新事件引用旧编号。相同对象和维度采用时间最后的明确评价，显式“未评价”可撤回当前评价，保留历史。旧版本反馈不能借给新版。

仅补反馈时先保存旧 revision 快照，核对并发变化，再增加 revision。变更范围、依据、风险判断或控制结论时新建分析批次，保留旧报告、编号映射和反馈。

## 查看流程

用户说“查看这次风险分析的效果，记录在……”，读取明确指定的报告和反馈：

1. 核对 run_id、版本、分析文件及反馈对象是否对应；不一致先标版本不符，不混算。
2. 先列尚未处理的重大遗漏、误报/过度定级、控制证据缺口及阻塞设计的问题，保留位置和下一步。
3. 分开展示风险处置进展、实际使用情况和技能表达/判断质量。风险已确认、已接受、已验证、已消除分别引用真实依据，不由状态名称推断。
4. 展示每个维度最后一次实际评价及原话、来源和历史反证；没有反馈明确未评价。
5. 需要数量时给原始条目数；任何评价比例只以该对象该维度真实非“未评价”的评价为分母。没有分母不报0%/100%，重复反馈不重复算成功风险。
6. 给具体改进提案及应验证的反例。改 skill 属于维护请求，按本轮实际授权处理，不由一次业务反馈自动改通用规则。

查看只读报告、反馈及用户获准的相关证据，不重新分析整个需求、不执行验证、不自动询问他人或安排回访。

没有真实使用记录写“尚无使用记录”，不推断从未被用过。无可比前后基线不报告节省时间、减少漏测或风险下降幅度。作者自审、结构校验、风险数量及关闭率只证明对应范围，不能代替实际收益。
